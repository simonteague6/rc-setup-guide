Setup Guide

Set up VS Code and Git on macOS or Windows.

I'm on macOSApple Silicon or Intel I'm on WindowsWindows 10 v2004+ or 11

Both paths lead to the same place: everything from "VS Code is open" onward is shared.

Path 01

macOS

Three steps to a working terminal and editor on macOS, then continue to the shared VS Code setup.

Reference: VS Code setup docs

1

Install Xcode Command Line Tools

Open Terminal first: press Cmd+Space, type Terminal, and hit Enter (or find it in Applications → Utilities). Every command in this guide runs there.

These provide git, compilers, and other developer tools that macOS doesn't ship with. Installing them first avoids "command not found" errors later. 

xcode-select --install
Why this comes first

Xcode CLI tools give you git, compilers, and other command-line utilities that other developer tools depend on. Installing them first avoids "command not found" errors later.

2

Install VS Code

Install with Homebrew if you already use it, or download VS Code directly.

Recommended path: Homebrew
Tip: install Homebrew first

Homebrew is a package manager that makes installing and updating dev tools one command. It's recommended but not required. 

sh -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

Then visit brew.sh if you need more detail.

With Homebrew installed:

brew install --cask visual-studio-code
Quick path: direct download

Visit code.visualstudio.com/download, download the .dmg, open it, and drag Visual Studio Code to Applications. VS Code handles its own updates.

3

Open VS Code

Launch VS Code from Applications. You'll open a project folder in the shared setup below.

You're set. VS Code is open. Continue to the shared setup.

Path 02

Windows

Set up WSL and Git on Windows, then connect VS Code to Ubuntu and continue to the shared setup.

Reference: VS Code setup docs

1

Install WSL

WSL gives you a real Ubuntu Linux environment inside Windows. This requires Windows 10 v2004+ or Windows 11.

Open PowerShell as Administrator: press the Start key, type powershell, then click "Run as Administrator" on the right. 

wsl --install

If the install succeeds, reboot when prompted. If it fails or Ubuntu won't start afterward, open the help below.

WSL won't install or Ubuntu won't start? Check virtualization

Open Task Manager (Ctrl+Shift+Esc) → Performance → CPU and look for "Virtualization: Enabled." If it says Disabled, turn on virtualization in BIOS. Common setup keys are below:

Brand BIOS Setup Key
Dell F2
HP Esc → F10
Lenovo F1 or F2
ASUS F2 (laptop) / Del (desktop)
Acer F2
Other Del or F2

Restart and press the BIOS setup key as the computer starts. Find the virtualization setting (often called Intel VT-x or AMD SVM), enable it, save, and reboot. Then retry wsl --install. If Task Manager already says Enabled, check Windows Update or ask for help with the exact error message instead.

Why WSL

The club project and the tools in this guide run on Linux. WSL gives you a real Ubuntu shell and filesystem without dual-booting or a virtual machine GUI.

2

Ubuntu First Launch

After reboot, Ubuntu launches automatically (or open it from the Start menu). It asks you to create a Unix username and password. Choose any, and remember the password: you'll use it with sudo.

The password won't show as you type

No characters, dots, or asterisks appear while you type your password — this is normal terminal behavior, not a stuck screen. Keep typing, then press Enter.

3

Update Ubuntu

Fresh Ubuntu is out of date. Bring it current. 

sudo apt update && sudo apt upgrade -y
4

Install Git in Ubuntu

Run this in the Ubuntu window:

sudo apt install git -y
5

Install VS Code on Windows

Download and run the Windows installer from code.visualstudio.com/download. If the installer offers Add to PATH, check it so the code command works from Ubuntu.

6

Install the WSL extension

Open VS Code on Windows. Click Extensions in the left sidebar (Ctrl+Shift+X), search for WSL by Microsoft, and click Install. Here's the WSL extension on the Visual Studio Marketplace.

7

Connect to Ubuntu in VS Code

Press Ctrl+Shift+P, type WSL: Connect to WSL, and press Enter. Choose Ubuntu if asked. Wait for VS Code to connect; the bottom-left corner should say WSL: Ubuntu. Click that corner if you need to switch connections later.

Keep projects in Ubuntu

Use your Linux home (~), not /mnt/c/Users/.... Check for WSL: Ubuntu in the bottom-left before opening a project or terminal.

Open the VS Code terminal with Ctrl+` (backtick, near the top-left of your keyboard). Once connected to WSL, a new terminal opens in Ubuntu. Run cd ~ before cloning so the project lives on the Linux side.

For more detail, see VS Code's WSL guide.

From here on, macOS and Windows are identical. Continue to the shared shared setup.

In VS Code

Setup inside VS Code

You're in VS Code with Git installed. These steps are the same on macOS and Windows.

1

Clone the Practice Repo

You'll clone simonteague6/rc-first-pr-practice. Use it to get familiar with the editor now; the first pull request comes later.

Open VS Code's built-in terminal with Ctrl+` (backtick, left of 1). On Windows, check for WSL: Ubuntu in the bottom-left and run cd ~ first. Run these commands one at a time: 

mkdir -p ~/projects
cd ~/projects && git clone https://github.com/simonteague6/rc-first-pr-practice
cd rc-first-pr-practice && code .

code . opens the folder in VS Code. You should see README.md and a names folder. On macOS, if code is not found, open the Command Palette (Cmd+Shift+P), run Shell Command: Install 'code' command in PATH, and reopen the terminal.

First time using git? Set your name and email

If you've never used git before, set your name and email so any commits you make later are attributed to you. These only need to be set once; git remembers them. 

git config --global user.name "Your Name"
git config --global user.email "your@email.com"
2

Verify Your Environment

Check that Git is working inside the cloned folder. 

git status

You should see On branch main and a clean working tree.

Now take a quick tour of VS Code → VS Code UI Tour.

Tour

VS Code UI Tour

With the example project open, try these parts of the editor.

Explorer and file picker

The Explorer on the left shows the project's files. Click one to edit it in the center. Use Cmd+P on macOS or Ctrl+P on Windows to find a file by name.

Command Palette

Press Cmd+Shift+P on macOS or Ctrl+Shift+P on Windows, then type an action. On Windows, search for WSL: Connect to WSL here if you need to reconnect.

Source Control

Click the branching icon in the left Activity Bar to see changed files. Click a file to see its diff. Your current branch appears in the bottom-left status bar; click it to see other branches. To see the project's history in the terminal, run git log --oneline --graph --all.

Terminal

Press Ctrl+` to open the terminal inside VS Code. On Windows, check that the bottom-left status bar says WSL: Ubuntu so your terminal runs in Linux.

More about the editor: VS Code user interface guide.

Next Steps

Your environment is ready. Now the fundamentals.

Version control is a system that records changes to your files over time so you can undo mistakes, experiment safely, and work alongside teammates without overwriting each other's code. Git is the tool; GitHub is where the club stores its repositories.

The unit of version control is the commit, a saved snapshot with a message that describes what changed and why. Think of it like a checkpoint in a game: you can always get back to a working state, no matter how far you've wandered.
